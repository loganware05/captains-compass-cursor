# Bend policy-lifecycle proof spike (#278)

Plan: `bend-policy-proof-spike` · durable plan [`../plans/BEND_POLICY_PROOF_SPIKE.md`](../plans/BEND_POLICY_PROOF_SPIKE.md) · ADR-110 (Proposed) · evidence `.agent/evidence/bend-policy-proof-spike/`

An **opt-in, additive experiment**. It machine-checks the *decision core* of the policy lifecycle
(`orchestrator/behavior/policy/states.py`, plus the gate structure of `promote.py`) against a
[Bend 2](https://github.com/bendlang/bend) model and proofs. It changes no production behavior, adds
no required dependency and grants no authority (`authority_mutation=false`,
`approved_for_execution=false`).

## Run it

```bash
COMPASS_BEND_PROOF_ENABLED=1 ./scripts/northstar formal check policy-lifecycle
COMPASS_BEND_PROOF_ENABLED=1 ./scripts/northstar formal check policy-lifecycle \
  --strict-laws --base-ref origin/main      # Captain-owned laws vs base; fails closed
COMPASS_BEND_PROOF_ENABLED=1 ./scripts/northstar formal lock policy-lifecycle   # refresh drift lock
```

Without the flag the command exits `2`. With the flag but without the toolchain, the check reports
`skipped` (default CI/doctor stay green) — **unless** drift or a strict-laws failure is detectable
without the toolchain, in which case it fails. An explicit `COMPASS_BEND_BIN` that is missing fails.

## Toolchain

Project-local and git-ignored under `.agent/tools/` (never a global install). Bend release `v2.0.40`
(archive sha256 cross-checked against two origins) and Lean `v4.34.0` for `--verdict`. Provenance:
`.agent/evidence/bend-policy-proof-spike/wave0-provenance.md`.

| Variable | Meaning |
|---|---|
| `COMPASS_BEND_PROOF_ENABLED` | Required (`1`/`true`/`yes`/`on`); enforced in library entry points, not just the wrapper |
| `COMPASS_BEND_BIN` | Explicit compiler path; never falls back if missing |
| `COMPASS_BEND_SHA256` | Optional pin; mismatch is refused. Evidence records `pinned: false` when unset |

The compiler runs with an environment **allowlist** (no tokens/keys forwarded), in its own process
group with a timeout and clipped output, with `BEND_NO_TELEMETRY=1`.

## What is proved

Files in `formal/bend/policy-lifecycle/`:

| File | Owner | Role |
|---|---|---|
| `Model.bend` | agent | the model (`decide`, `next`, `run`, `apply`) |
| `SPEC.bend` | **Captain** | independent observers/vocabulary so a mutated model cannot satisfy laws vacuously |
| `LAWS.bend` | **Captain** | the 17 laws |
| `PROOF.bend` | agent (generated by `gen_proof.py`) | proofs; checked with `bend … --verdict` (Lean-proven kernel) |
| `Conformance.bend` | agent | prints the 1568-row decision grid |
| `tables.lock.json` | agent | drift lock: tables + `promote_policy` gate structure + law manifest |

Laws: P1 legality · P2 Captain gate · P3 terminal (P3′ over arbitrary sequences) · P4 forward-only
(per step) · P5 shadow-before-approval (per step) · P6 no authority grant · P7a–d evidence gates ·
P8a/b `next` · P9a/b `run` · P10 outcome agrees · P11 liveness (a model that rejects everything satisfies every safety law, so this one forces acceptance of the full happy path).

## Conformance and controls

- **Differential grid:** 7 states × 7 × captain × 16 evidence combinations = 1568 rows; the Python
  reference calls the real `can_transition` / `require_captain_approved` and extracts the gate
  structure of `promote_policy` with `ast`.
- **Drift lock:** pins the tables, the extracted gate structure, a hash of the *whole* `promote_policy` AST
  (so any edit there needs a re-prove + re-lock), the binding identity of `can_transition` /
  `require_captain_approved`, the law manifest, and the hashes of `Model.bend` / `Conformance.bend`.
  The lock is regenerated by the same agent, so its **diff is what the Captain reviews**.
- **Mutation controls:** 23 model mutants (each must trip its *declared* law, or be caught by the
  evidence grid alone for restrictive mutants) and 15 Python-side mutants: 9 are visible to the grid,
  and 6 are "evasions" (same gates called, different behavior) that the grid and extractor cannot see and
  only the AST-pin lock catches. 38/38 on the recorded run.
- **Law integrity:** `--strict-laws --base-ref` compares `LAWS.bend`/`SPEC.bend` with the base; a bad
  ref is an error (never "clean"); files absent at base count as changed.

## Known gaps (stated, not hidden)

1. P4/P5 are proved **per accepted step**, not over whole histories (Amendment A1; Captain review).
2. Evidence gates are booleans; their filesystem checks are not modeled.
3. Gate order in `promote_policy` is pinned by the lock, not proved.
4. **Finding 001** — historical direct entry into `proven` via `ensure_policy_for_instruction`
   (production fixed in #280; Bend entry-state law still a #278 follow-up). See
   `.agent/evidence/bend-policy-proof-spike/finding-001-direct-entry-bypass.md`.
5. P6, P8 and P10 are about the model (`finish` hard-codes no authority); nothing links them to production
   code except the AST pin on `promote_policy`.
6. The AST pin is coarse: it detects *any* edit to `promote_policy`, benign or not.
7. Lean (the strongest check) is not pinned, and the optional Bend pin is checked at discovery, not at exec.
8. `--base-ref` is caller-chosen (`HEAD` compares against itself); there is no pinned approved SHA.
9. A run with `--no-verdict` or `--no-mutations` reports `status: partial` / `degraded: true`.
10. CI wiring of `--strict-laws` is deferred pending the go/no-go.
